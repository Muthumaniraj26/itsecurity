When you use Professional or Enterprise tiers, you can input your own Google Gemini, OpenAI, or Anthropic API keys directly in Account Settings. Keys stay in client storage and are passed via secure ephemeral headers directly to the inference endpoint.

Platform Overview

Security Intelligence is an enterprise autonomous threat analysis platform engineered to accelerate security investigations, correlate raw threat feeds, inspect suspicious target links, and produce deterministic, evidence-backed security advisories.

Core Philosophy: Decouple verifiable empirical facts (DOM scraping, SSL certificate properties, RDAP registration age) from probabilistic LLM reasoning. Security analysts always receive transparent telemetry alongside AI recommendations.

Key Capabilities

  • Threat Digest Hub: Continuous ingestion of official vulnerability feeds from CISA, BleepingComputer, and ZDI with automated CVE and MITRE ATT&CK tagging.
  • URL Phishing Sandbox: Comprehensive inspection of web links against the 30-factor University of California Irvine (UCI) heuristic benchmark.
  • Website Scam Risk Detector: Automated RDAP/WHOIS domain registration audits, policy compliance scans, and commercial fraud pattern detection.
  • SBOM Dependency Scanner: Manifest vulnerability auditing (requirements.txt, package.json) cross-referenced against the CISA Known Exploited Vulnerabilities (KEV) catalog.

URL Phishing & 30-Vector Heuristic Engine

Our phishing sandbox inspects target links across 30 deterministic heuristic signals derived from the University of California Irvine (UCI) Machine Learning Phishing Dataset.

Safe Inspection Guarantee: The sandbox executes requests inside isolated network workers without executing malicious browser binaries or dangerous client scripts.

Evaluated Heuristic Vectors

Vector Heuristic Rule Risk Indication
having_IP_Address Host uses raw IPv4/IPv6 address instead of DNS hostname Common in fast-flux phishing landing pages
URL_Length URL character length > 75 characters Obfuscation and encoded token smuggling
Shortining_Service Uses bit.ly, tinyurl.com, t.co, or ow.ly redirectors Hiding true malicious destination host
having_At_Symbol URL contains "@" character before hostname Browser URL userinfo spoofing trick
double_slash_redirecting "//" occurs after position 7 in path Redirect parameter exploitation
Prefix_Suffix Domain contains hyphen (e.g. paypal-verify.com) Brand impersonation and typosquatting
Sub_Domain More than 3 subdomain dots present in host Multi-layered subdomain cloaking
SSLfinal_State Invalid certificate, expired issuer, or self-signed cert Untrusted TLS communication
Abnormal_URL Host does not match WHOIS identity / missing hostname Mismatched registration identity
SFH (Server Form Handler) HTML <form action> points to external domain or "about:blank" Credential harvesting form exfiltration

Website Scam Risk & RDAP Trust Auditor

The Scam Risk Detector investigates e-commerce stores, newly registered domains, and investment portals to assess the likelihood of commercial fraud or identity theft.

Investigation Methodology

  • RDAP Domain Age Verification: Performs authoritative Registration Data Access Protocol lookups against TLD registry servers. Domains younger than 30 days are automatically flagged with elevated suspicion.
  • Policy Compliance Inspection: Audits DOM text for mandatory legal agreements (Terms of Service, Return & Refund Policy, Physical Address Disclosures, GDPR/CCPA Privacy Notices).
  • Social & Payment Signals: Verifies whether listed payment processors are standard (Stripe, PayPal) versus irreversible payment methods (crypto addresses, Western Union, direct gift cards).

SBOM Dependency Vulnerability Auditor

Software Bill of Materials (SBOM) auditing scans project dependencies, extracts version constraints, and cross-references every package against public vulnerability catalogs and CISA KEV.

Sample SBOM Manifest (requirements.txt) 
urllib3==1.26.4
requests==2.25.0
flask==1.1.2
jinja2==2.11.2
cryptography==3.3.1

The scanner identifies vulnerable sub-dependencies, maps CVSS v3.1 scores, alerts if any library is present on CISA KEV, and outputs explicit minimum upgrade versions (e.g. Upgrade jinja2 to >= 3.1.4 to remediate CVE-2024-34064).

Evidence vs. AI Reasoning

A critical security requirement in enterprise environments is verifiable auditability. Our system maintains a strict barrier between Observed Telemetry and AI Synthesis:

1. Observed Evidence (Deterministic)

Empirical data points obtained directly from network sockets, DNS resolvers, and DOM parsers:

  • Exact HTTP response status codes & headers
  • Domain creation date & registrar handle
  • SSL certificate expiration & issuer CN
  • Matched CVE numbers in NVD database

2. AI Synthesis (Probabilistic)

Synthesized analysis provided by LLM reasoning models:

  • Executive impact summary
  • Contextual threat actor motivations
  • Mitigation steps tailored to stack
  • Confidence bounds estimation

Confidence Mathematics & Uncertainty Bounds

Every generated report includes a statistical confidence score (between 0.00 and 1.00) measuring data completeness:

Confidence Calculation Formula 
Confidence = 0.40 * (Features_Retrieved / Total_Possible_Features)
           + 0.30 * (RDAP_Data_Completeness)
           + 0.30 * (Vulnerability_Database_Confirmation)

If a target domain blocks WHOIS queries or obscures DNS responses, the system lowers the confidence score and displays an alert indicating that additional telemetry is required for a conclusive rating.

Developer Integration Code Samples

Easily incorporate security intelligence scans into your automated CI/CD pipelines, SOAR playbooks, or custom Python tools.

Python Integration Example

python_scanner.py 
import requests

API_URL = "http://localhost:8000/api/v1/analyze/url"
headers = {
    "Content-Type": "application/json",
    "x-llm-provider": "google"
}

payload = {
    "url": "https://suspicious-domain.xyz/login"
}

response = requests.post(API_URL, json=payload, headers=headers)
data = response.json()

print(f"Risk Rating: {data.get('risk_level')}")
print(f"Confidence: {data.get('confidence') * 100}%")
for item in data.get("evidence", []):
    print(f" - [Evidence] {item}")

Incident Response Triage Playbooks

When an audit returns Critical or High severity, execute the following remediation sequence:

  1. Isolate Network Egress: Blacklist the flagged domain or IP on enterprise perimeter firewalls and recursive DNS resolvers (e.g., Pi-hole, Cisco Umbrella, Cloudflare Gateway).
  2. Export Advisory: Click Export Markdown to obtain the full SHA-256 evidence digest and attach it to your incident ticket.
  3. Audit User Inbound Logs: Search mail gateway logs (Microsoft 365 / Google Workspace) for matching domain strings to identify users who clicked or submitted credentials.
  4. Credential Rotation: Trigger mandatory multi-factor authentication reset for exposed accounts.

Encrypted Local Storage & Privacy

Privacy and operational security are built into the core design of Security Intelligence.

  • No Centralized Telemetry: Analyses, scan histories, and saved reports reside exclusively in your local SQLite database file located in the application directory.
  • Zero Key Retention: External model keys (Gemini, OpenAI, Anthropic) reside in browser localStorage and are never written to database tables or server logs.
  • Salted Password Hashes: User credentials are protected using salted SHA-256 hashes with individual cryptographic salts per account.

Air-Gapped & Offline Deployments

To deploy the platform in isolated environments without public internet access:

Air-Gapped Environment Configuration (.env) 
OFFLINE_MODE=true
LOCAL_RDAP_PROXY=http://192.168.1.50:8080/rdap
LOCAL_CVE_MIRROR=http://192.168.1.50:8080/nvd-mirror
DEFAULT_LLM_PROVIDER=custom
CUSTOM_LLM_BASE_URL=http://localhost:11434/v1
CUSTOM_LLM_MODEL=llama3:8b

In this mode, the platform routes all inference queries to local Ollama/vLLM servers and uses internal mirrors for CVE and RDAP lookups.
